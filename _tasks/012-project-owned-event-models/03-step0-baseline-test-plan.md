# Step 0 — Editor baseline: test and implementation plan

Status: proposed; planning only. This expands [Step 0](./02-plan.md#0-pin-current-behavior), not the project-local store or CLI work. The outcome is executable regression coverage of the **current IndexedDB-backed editor** plus a short human smoke checklist. No event schema, storage adapter, or editor behavior changes belong in this step.

## Approach and boundaries

- Use a small **real Chromium end-to-end suite** against the Vite-served `slicr-editor`. Prefer the standalone Playwright test runner for this suite because a full `page.reload()` must exercise startup and IndexedDB replay without restarting a Vitest browser test page. Playwright and the Vitest Playwright provider already exist elsewhere in the monorepo; the editor needs its own explicit runner dependency/configuration. Do not replace existing Vitest unit/React tests.
- Add only a handful of behavior-oriented browser tests; keep event parsing/decider details in Vitest. In particular, retain and extend `apps/slicr-editor/src/App.backupRestore.integration.test.tsx` and `src/application/eventBackup.test.ts` for backup failures/cancellation and event-format assertions. A browser backup/restore round-trip should also check the user-visible result with the real IndexedDB store.
- Assert observable project/chapter names, graph node labels and edited content, not generated UUIDs, canvas coordinates, CSS layout, screenshots, or internal event counts. Use the actual canvas graph node, not the unrelated mockup cards in `App.tsx`.
- Never point tests at a user's running editor/profile. Every test starts in a fresh browser context and isolated origin storage; within one test, preserve the same context across navigation/reload. Do not globally clear IndexedDB between the edit and reload assertions. Keep test setup through the UI unless a narrowly justified deterministic fixture is necessary; no direct store mutation to simulate user actions.

## Test matrix (implemented against current behavior)

| Case                     | Action and observable assertions                                                                                                                                                                                                                                                                                                                                             | Main regression protected                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Open workspace           | Visit a clean editor origin, wait for initialization, verify the initial project/chapter is selectable and a graph workspace is displayed; use `+ New Slice` if an initial slice is not present.                                                                                                                                                                             | Initial workspace/bootstrap and usable editor startup.                                            |
| Edit a node              | In that workspace, create or locate a real graph node, edit its label through the graph node's double-click/Enter interaction (and, if practical, an example property through the detail panel); verify the new label/content is displayed.                                                                                                                                  | UI → scoped command → graph projection.                                                           |
| Switch scope             | Create/select a second project and chapters via project switcher/sidebar; put distinct node labels in two scopes; switch away and back and assert the active project/chapter and each scope's own node visibility.                                                                                                                                                           | No cross-project/chapter bleed and correct selection/projection.                                  |
| Reopen persisted history | After at least one edit and scope change, reload the _same page/context_ (`page.reload()`) and verify the persisted project, chapter, and edited node can be found again. Re-select scope after reload if selection is UI-local; do not require selection itself to persist unless current behavior does.                                                                    | Actual IndexedDB write, startup replay, and browser reload.                                       |
| Backup/restore           | Through the toolbar, copy a full version-1 event backup to the clipboard, make a subsequent edit, restore the captured backup with confirmation, verify the earlier state returns and the later edit disappears, then reload and check it remains restored. Assert backup structure minimally (`version: 1`, `events` array); use existing Vitest tests for detailed format. | User-visible clipboard backup, destructive replacement, projection refresh and persisted restore. |
| Failed/cancelled restore | Extend existing app/service integration tests: cancel confirmation or submit invalid/unsupported backup; assert previous model and exported backup remain unchanged, and error feedback where applicable.                                                                                                                                                                    | No silent loss of existing history on a rejected restore.                                         |

If any proposed assertion disagrees with the present editor, first verify manually and record the actual behavior; Step 0 should pin the working baseline, not introduce a new requirement or hide a regression by weakening assertions.

## Implementation tasks

1. **Wire the editor browser suite.** Add an explicit editor dev dependency on a compatible `@playwright/test` version (and update the npm lockfile). Add `apps/slicr-editor/playwright.config.ts` with Chromium, localhost-only Vite `webServer`, a dedicated port with strict-port behavior, `baseURL`, bounded timeouts, CI-safe worker/retry settings, and failure-only trace/screenshot artifacts ignored by Git. Add `test:browser` to `apps/slicr-editor/package.json`. Ensure browser binaries are installed/document `npx playwright install chromium` for first-time setup/CI. Do not depend on undeclared, hoisted workspace packages.
2. **Make browser execution part of validation.** Decide the smallest script change so root `npm run validate:llm` exercises these regressions (for example, chain editor `test:browser` from editor `test:llm`, while preserving the existing Vitest LLM reporter). Avoid launching two simultaneous servers on the same port; check that normal `npm run test:llm --workspace=slicr-editor` remains concise. Document the focused browser-only command separately.
3. **Implement isolated browser flows** under `apps/slicr-editor/e2e/`. Start at least one test from a clean context, edit real nodes through accessible labels where available, switch scopes, reload the same context and assert replay. Use Playwright auto-waiting assertions rather than arbitrary sleeps; wait for debounced edits by an observable result and, where required, the backup/export boundary before reloading. Avoid claiming persistence based solely on a DOM update before the store write completes.
4. **Exercise clipboard restore in Chromium.** Grant clipboard read/write permissions for the local origin (or use a test-scoped browser clipboard shim only if real permissions are unreliable), capture the JSON after the backup toolbar action, write it back before restore, accept the confirmation dialog, and assert state before and after a real reload. Keep tests serial only where they intentionally share state within one context; otherwise use independently isolated contexts.
5. **Augment existing Vitest integration coverage** for cancellation, invalid JSON/unsupported version and preservation of data on failure where coverage is missing. Prefer verifying the backed-up event stream before/after rather than relying only on an alert. Do not duplicate all existing backup parsing unit cases in Playwright.
6. **Write the manual checklist** in a short `04-step0-smoke-checklist.md` beside this plan, with startup, node editing, scope switching, reload and backup/restore, a place to record date/browser/commit and observed failures. Run it once on the Step 0 branch; record any known pre-existing failure separately, rather than modifying application code in this baseline change.

## Verification and exit gate

- Focused: `npm run test:llm --workspace=slicr-editor` and `npm run test:browser --workspace=slicr-editor` (the latter may already be included by the former once wired). Browser tests must run in CI/root validation, not just locally.
- From repository root after editing: `npm run format` then `npm run validate:llm`; follow with the manual smoke checklist for user-facing paths. Keep test artifacts out of Git.
- At the stopping point, the editor still uses the existing IndexedDB history with its in-memory fallback outside a browser, existing workflows remain intact, no `.slicr/` history is created, and tests prove a saved model survives reload and a confirmed backup restore. Record the test command and any environmental prerequisite in the checklist.
