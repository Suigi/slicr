# Step 6 scope changes

Step 6 adds `slicr serve [--port PORT]` in `apps/slicr-cli/`. It hosts a dedicated read-only project view backed by the selected project directory's `.slicr/events.ndjson`, plus versioned `/api/model` and `/api/projection` JSON endpoints. The page supports project and chapter selection and displays projected nodes, schemas/examples, connections, stable IDs, revision, and the opened project/store paths. It does not load the existing editor application because that application still writes to browser IndexedDB; serving it with a project-model banner would falsely imply synchronization. Existing editor startup and IndexedDB behavior are unchanged.

The server defaults to `127.0.0.1`, restricts request Host headers to loopback hostnames/addresses, and verifies resolved static-file paths remain under the configured asset root. Read requests do not initialize or rewrite a missing/corrupt store. Tests cover API projections, invalid references, read-only view structure, missing/corrupt storage, untrusted Host rejection, static symlink escape rejection, and server shutdown. The first review's blockers around a misleading writable editor page, Host validation, and symlink traversal were addressed. A CLI-process SIGINT test was attempted but hung under node:test and removed; signal-shutdown process coverage and browser visual smoke remain outstanding. Direct server shutdown is tested.

Verification on Node 24.21.0: CLI tests pass 20/20 after review fixes; `npm run format` and root `npm run validate:llm` pass, including editor browser tests (3/3) and typecheck. Independent reviews found that the first read-only page did not initialize rendering and omitted revision/schema/examples, that graph projection stripped node chapter IDs, that the connection section was built but not attached to the page, and that chapter lookup must account for duplicate node IDs across projects. These were fixed: the page attaches the connection section; node-to-chapter lookup uses the composite project/node identity; and regression tests cover an ID reused across projects.
