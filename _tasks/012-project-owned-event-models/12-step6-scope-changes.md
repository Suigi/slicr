# Step 6 scope changes

`slicr serve` now hosts a **dedicated build of the actual slicr-editor frontend** (`dist-project/project.html`) rather than an inline projection preview. The separate read-only entry point reuses the editor's canvas, node cards, property grids, edge routing, measurement and layout, while fetching workspace and scoped graph projections from `/api/model` and `/api/projection`. It displays the selected project directory, `.slicr/` store, revision and a permanent read-only indication. Project/chapter selection is available; editing, backup/restore, node menus, property editors, keyboard mutation shortcuts and mockup editors are absent. The read-only bundle never imports the normal App or IndexedDB startup, and the server only serves the isolated project build. The normal editor entry and IndexedDB startup remain unchanged. The two histories are not synchronized.

The local API remains GET/HEAD only, bound to loopback by default, with Host validation and static-file confinement including symlink checks. Reads do not create or rewrite missing/corrupt stores. Event history batches, event payload schemas and canonical tags are validated before projection; malformed and unsupported history, including inherited property names such as `__proto__`, is rejected as 422 from both read APIs. No Step 7 write API, migration or cutover is included. Browser coverage opens the actual built frontend against a CLI-created project history, verifies API-backed graph/chapter rendering, absence of editing controls and IndexedDB initialization, reload, and unchanged event bytes after attempted interactions. CLI tests cover API reads, errors, identity, path/Host checks and shutdown. The project frontend is built via `npm run build:project --workspace=slicr-editor` (also part of the normal editor `build`). The final high-effort `gpt-6-sol` review found no Step 6 blockers. CLI tests passed 22/22, project browser tests 2/2, and full root `npm run validate:llm` passed. Step 7 hardening later corrected two review findings in this served foundation: valid property-only example values are accepted, and `slicr serve` now fails fast with build guidance when required assets are absent. Human visual smoke and subprocess signal-shutdown tests remain outstanding.
