# Step 5.1 scope changes

Step 5.1 adds explicit `slicr init`, which refuses non-empty or incompatible stores but can seed a valid existing empty event log; reads never initialize storage. Successful `init` now records a `Default Project` and `Default Chapter` through the shared initial-workspace decider; this is a user-directed change from the plan's earlier no-domain-events initialization target. CLI inspection now uses the shared `slicr-core` workspace and graph projections. Project selection is named (`--project PROJECT_ID`), never positional; it is optional only when there is one project and required when there are several. `chapters`, `show`, `rename-project`, `add-chapter`, `add-node`, `rename-node`, and `connect-nodes` all use this project selection. Mutations (`add-project`, `add-chapter`, `add-node`, `rename-node`, `connect-nodes`, and the prior `rename-project`) run through shared deciders and `handleCommand` with `NdjsonSpecEventStore`; output includes generated IDs where applicable and the revision hash of the exact resulting event-log bytes.

The CLI runs shared TypeScript modules using Node 24's built-in type stripping and a `register()`-registered resolver hook. `GraphProjector` uses an explicit field assignment instead of a parameter property, so the module graph needs no experimental transform-types flag. Event histories must contain the query tags emitted by the shared event constructors; the CLI does not infer or repair missing tags. Commit `321455b` removes the unsupported tag-repair compatibility code and replaces synthetic tagless fixtures with well-formed events created by shared constructors. Commit `69c6fdc` adds default-workspace initialization (including safe seeding of an existing empty event log) and named project selection with single-project inference and multi-project ambiguity errors. CLI tests cover new and empty-store initialization, refusal to overwrite existing events, project selection, valid scoped mutations, invalid references and inputs, no-op decisions, generated IDs, exact revisions, reopening in another process, and conditional conflicts across independent shared-handler workers.

Verification on Node 24.21.0: `npm run test:llm --workspace=@slicr/slicr-cli` passed 15/15; `npm run format` passed; `npm run validate:llm` passed (lint, all workspace LLM tests including the browser tests, and typecheck). Existing React `act(...)` and Vite native-config warnings were non-fatal.

Review: final independent `gpt-6-sol` review found no blockers. Residual limitations: concurrency coverage races separate shared-handler workers, not full simultaneous CLI processes; no-op decisions return before conditional append/CAS; and the init close-failure cleanup path has no injected-failure test. Browser IndexedDB remains unchanged and separate from project `.slicr/`. No Step 6/7 behavior is included.
