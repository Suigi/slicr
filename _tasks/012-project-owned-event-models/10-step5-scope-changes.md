# Step 5 scope changes

Step 5 adds the single `rename-project PROJECT_ID NEW_NAME` CLI mutation through `packages/slicr-core`'s `deciders().renameProject` and the shared `handleCommand`, backed by `NdjsonSpecEventStore`. Node 24's `--experimental-strip-types` and `scripts/ts-resolve-hook.mjs` load the existing TypeScript dependency graph. Successful output includes append count and SHA-256 of the exact resulting `.slicr/events.ndjson` bytes.

Coverage verifies unknown-project failure appends nothing, a successful rename is visible to a subsequent fresh CLI process, the returned revision matches the exact log bytes, and two independent Node processes using the shared command handler synchronize after reading the same initial state: one succeeds and the other receives `AppendConditionFailedError`. Fixture event tags now match the shared event constructors.

The CLI is now an npm workspace application at `apps/slicr-cli/`, committed as `3a3562b feat(slicr-cli): move CLI into workspace package`; the prior CLI implementation is committed as `e398f6b feat(cli): add project model edits`. Its `slicr` bin resolves workspace source from the application location, so installed-bin use from an unrelated project directory does not depend on the caller's current directory. The root `npm run slicr -- …` script forwards arguments to that bin. This supports use from another project while working in the monorepo, but it is not yet independently installable: the CLI/runtime workspace packages remain private and rely on monorepo source.
