# Step 4 scope and provisional choices

- For Steps 4–7, use the Step 3 NDJSON-authoritative adapter as the provisional project-store choice; this is not a final storage-format decision. The SQLite spike and its findings remain intact.
- The read-only CLI reads and validates `.slicr/events.ndjson` directly and does not open the adapter, because `open()` also creates/rebuilds the runtime outbox database. Thus CLI reads are strictly non-mutating; adapter lock/recovery behavior is not applied during inspection.
- Step 4 correction after re-review: retain the direct Node implementation, align graph projection with shared semantics (source→target connections, disconnect removal, self-connection exclusion, and chapter slices containing only edges whose two endpoints are in the slice), expose schema/example-value changes, and reject unknown event types. Projection keys use collision-safe tuple encoding; all node/edge updates, removals, disconnects, and cleanup are scoped by project ID so reused or delimiter-containing IDs cannot cross-contaminate projects. `show` validates extra positionals around `--format`; reads remain non-mutating and use exact-file-byte SHA-256 revisions.
- Markdown `show` includes each node's schema and example values inline beneath its readable node entry when present, as well as connections, so the scoped slice details are available in either output format.
- Revision remains SHA-256 of exact canonical file bytes, suitable as a read token but not yet wired to guarded writes. Commands implemented: projects, chapters, and show JSON/Markdown. No initialization or mutation command is present.
- This does not modify IndexedDB or frontend behavior. The NDJSON format, compatibility upgrades, history Git policy, symlinks, and final store selection remain unresolved. The Step 3 outbox cleanup/recovery caveats continue to apply to future writers.
