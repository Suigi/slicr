# Step 7 scope changes

Step 7 implements a bounded served-editing slice, not the planned IndexedDB migration/cutover.

- Added a loopback-only `POST /api/command` endpoint to `slicr serve`. It accepts allowlisted, project-scoped shared commands (`RenameNode`, `AddNode`, `ConnectNodes`, `AddChapter`, `RenameProject`) and routes them through the same `NdjsonSpecEventStore`, shared deciders and `handleCommand` used by CLI operations. Command field types and domain values are validated before invoking shared handlers; requests require the latest read's `baseRevision`, and stale views or append-condition conflicts return actionable HTTP 409 responses. Writes require `application/json` and reject foreign `Origin` headers.
- The dedicated project frontend can add a node and rename a node through this API. The normal editor entry and its IndexedDB default write path were not changed.
- Project projection/model reads are recomputed from disk. The served frontend polls these read APIs, so independent CLI/store writes become visible without relying on process-local subscriptions; subsequent CLI reads observe browser appends in the shared NDJSON history.
- Regression coverage exercises served command persistence, malformed-command rejection without any history-byte changes, invalid reference rejection, stale browser-vs-CLI writes over HTTP, a deterministic revision race that turns a command into a no-op, atomic store revision rejection, content-type and Origin protections, property-only `NodeExampleValuesChanged` entries, and visibility of both served-editor and independently appended changes on the next API read. Existing independent-process conditional-append race coverage remains in the CLI suite.
- The served editor polls sequentially with cancellation on view changes/unmount, uses a generation guard so older poll responses or errors cannot override a newer post-write refresh, surfaces refresh errors separately from command errors, retains stale-edit guidance while keeping the canvas available, and allows the user to refresh and retry. Post-write refresh failures are reported separately from command outcomes. `slicr serve` preflights `project.html` and its built `/assets/` references before listening, with an actionable build command; CLI startup now states that editing is enabled.

## Explicitly deferred

The migration from existing IndexedDB histories, destination collision policy, backup/import verification, rollback path, migration smoke tests, and removal/replacement of the default IndexedDB write path are **not implemented**. This follows the user's explicit decision to defer migration/cutover. The regular editor remains IndexedDB-backed, separate from the `.slicr/` store; it is not synchronized with `slicr serve`, and no synchronization or completed cutover is claimed. Do not migrate users or remove the old write path based on this step.

The served editing surface is intentionally incomplete: current UI mutation controls expose node creation and node rename; the API additionally supports a small set of other scoped commands but does not yet expose full editing parity (for example property editing, node removal/type changes, and connection gestures). The browser E2E and API integration tests cover editing/catch-up, a server restart, stale edit guidance and retry, out-of-order polling, superseded poll failures, post-write refresh failure reporting, and revision-guarded appends. The revision hash is rechecked inside the NDJSON store's cross-process transaction at append time, closing the validation-to-write gap. A human visual smoke check and migration/recovery remain outstanding.
